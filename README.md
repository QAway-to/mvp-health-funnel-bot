# mvp-running-landings

Два продающих лендинга онлайн-гайда по естественной технике бега. Один продукт, две аудитории:

| Маршрут      | Лендинг                | Аудитория                                             |
| ------------ | ---------------------- | ----------------------------------------------------- |
| `/bez-boli/` | **А — «Бег без боли»** | Болят колени. Обращение на «вы», спокойный тон.        |
| `/sila/`     | **Б — «Бег как сила»** | Уже тренируются в зале. Обращение на «ты», прямой тон. |
| `/`          | Развилка               | Выбор между А и Б для прямых заходов на корень.        |

Собрано по дизайн-хендоффу из `docs/design-handoff.md` — там же лежат оригинальные токены, размеры и описание всех секций.

## Стек

- **Astro 7** — статическая многостраничная сборка, ноль JS на клиенте кроме аналитики.
- Без UI-фреймворков и CSS-препроцессоров: токены в `src/styles/global.css`, остальное — scoped-стили в компонентах.
- Шрифты **Onest** (заголовки) и **Golos Text** (текст) с Google Fonts.

## Запуск

```bash
npm ci
npm run dev      # http://localhost:4321
npm run build    # сборка в dist/ + сжатие .br/.gz
npm start        # поднять сервер на dist/ (то же, что на Render)
npm run preview  # посмотреть собранное
npm run check    # проверка типов
```

Нужен Node ≥ 22.12 (зафиксирован в `.node-version` и `engines`).

## Структура

```
src/
├── config/site.ts        ← цены, ссылки оплаты, реквизиты — ОДНО место для правок
├── content/
│   ├── types.ts          ← схема контента лендинга
│   ├── landing-a.ts      ← весь копирайт лендинга А
│   ├── landing-b.ts      ← весь копирайт лендинга Б
│   └── nav.ts            ← общая навигация
├── components/           ← секции: Hero, Mirror, Reasons, Mechanism, Effects,
│                            Program, Plan, AuthorSection, Pricing, Faq, FinalCta
├── layouts/Landing.astro ← <head>, мета, OG, шрифты
├── pages/                ← index / bez-boli / sila / 404 / robots.txt
├── scripts/analytics.ts  ← события cta_click и scroll_depth
└── styles/global.css     ← дизайн-токены и примитивы
public/img/               ← шесть фотографий из хендоффа
```

Оба лендинга описаны одной схемой (`LandingContent`) и рендерятся одними компонентами — различаются только данными. Секция «Шесть эффектов» есть только у Б, план у А по дням, у Б по неделям (`plan.variant`).

## Что нужно сделать перед продом

### 1. Заменить плейсхолдеры

Все данные в фигурных скобках — `{ЦЕНА}`, `{ГАРАНТИЯ}`, `{ИМЯ_СПИКЕРА}` и прочие — лежат в **`src/config/site.ts`**. Правится один файл, оба лендинга подхватывают.

Отдельно проверить `site.url` — он идёт в canonical, OG-теги и sitemap.

### 2. Подключить платёжные ссылки

`site.links.payBase` и `site.links.payPremium`. Открываются в том же окне, как в хендоффе.

### 3. Заменить фотографии

`public/img/` — плейсхолдеры из исходного проекта. Особенно `mountain.jpg`: там должен быть портрет автора.

### 4. Подключить аналитику

`src/scripts/analytics.ts` отправляет `cta_click` (с `placement`: header / hero / price_base / price_premium / final) и `scroll_depth` (с `section`) в `window.dataLayer` и `window.gtag`. Счётчик не зашит — добавить GTM или gtag в `src/layouts/Landing.astro`, события поедут сами.

## Деплой на Render (Web Service)

Сайт разворачивается как **Web Service**: сборка отдаётся Node-сервером `server.mjs`, который слушает `PORT` и раздаёт `dist/`.

Настройки сервиса:

| Поле | Значение |
| --- | --- |
| Build Command | `npm install && npm run build` |
| Start Command | `npm start` |

Больше ничего задавать не нужно: версия Node берётся из `.node-version`, порт Render передаёт сам.

### Что делает сервер

Web Service — это обычный процесс, поэтому всё, что у статических хостингов лежит в конфиге, здесь реализовано в `server.mjs`:

- редиректы `/bez-boli` → `/bez-boli/`, `/sila` → `/sila/` и короткие `/a`, `/b` (query-параметры сохраняются, UTM-метки не теряются);
- `Cache-Control: immutable` на `/_astro/*` и `/img/*`, `no-cache` на HTML — правка цены доезжает сразу после деплоя;
- `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options`;
- `404.html` со статусом 404, а не 200;
- закрытие по `SIGTERM`, иначе каждый деплой ждёт таймаута.

### Сжатие

За Web Service ответы никто не сжимает — этим занимается сам сервер. `npm run build` после сборки кладёт рядом с текстовыми файлами `.br` и `.gz` (`scripts/precompress.mjs`), а `server.mjs` их отдаёт. HTML лендинга уезжает **6.9 КБ вместо 33.6 КБ**.

Шаг встроен в общий `build` намеренно: build-команда одна, перепутать её в настройках нельзя.

### Адреса со слешем

Страницы собираются папками (`dist/bez-boli/index.html`), поэтому канонический адрес — **со слешем**: `/bez-boli/`. За это отвечает `trailingSlash: 'always'` в `astro.config.mjs` — canonical, OG и sitemap согласованы между собой. Вариант без слеша уводится редиректом, так что рекламу можно вести на любой из них.

### Домен

Settings → Custom Domain, добавить домен, прописать CNAME у регистратора, дождаться сертификата.

**Затем обязательно** поменять переменную `PUBLIC_SITE_URL` на боевой адрес (Environment) и передеплоить — иначе canonical, OG-теги и sitemap останутся с адресом `onrender.com`: страницы откроются, но превью в мессенджерах и индексация будут указывать не туда.

### Про render.yaml

Файл в корне описывает альтернативный вариант — Static Site через Blueprint. **В текущей схеме он не используется**: поля `headers` и `routes` в нём работают только для Static Site и на Web Service не действуют. Источник правды для редиректов и заголовков — `server.mjs`.

## Отступления от прототипа

Прототип — HTML-референс из среды прототипирования, не продакшн-код. Копирайт перенесён дословно (проверено диффом текста), визуал воспроизведён по токенам. Осознанные отличия:

1. **Контейнер hero выровнен по общей сетке.** В прототипе он был флекс-элементом без явной ширины и сжимался по содержимому — левый край hero не совпадал с остальными секциями. Задан `width: 100%`, теперь все секции начинаются по одной линии в 1200px-контейнере.
2. **Хедер на мобильном в два ряда.** В прототипе три элемента переносились в три ряда и хедер занимал 167px из 844px экрана. Добавлен брейкпоинт (< 720px): логотип и кнопка в первом ряду, ссылки во втором — 109px. `scroll-margin-top` для якорей подстроен под обе высоты.
3. **FAQ оставлен раскрытым.** Хендофф помечает аккордеон как опциональный, а fidelity — high, поэтому вопрос и ответ видны сразу, в две колонки, как в макете. Добавлена разметка `FAQPage` (JSON-LD).
4. **Добавлены** `<title>`, `<meta name="description">`, OG-теги, canonical, favicon, `robots.txt` и sitemap — в прототипе их не было, хендофф требовал добавить.
