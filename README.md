# Health Funnel Bot

Telegram-бот Федерации Здоровья: отвечает на вопросы о беге и здоровье,
подкрепляет ответы короткими роликами по теме и доводит человека до покупки
программы. Воронка заканчивается внутри чата — наружу бот никого не уводит.

## Как это устроено

**Диалог.** DeepSeek отвечает строго по базе знаний из `prompts/persona.txt`.
Выдумывать факты ему запрещено — чего нет в базе, того он не скажет.

**Ролики.** Библиотека — приватный Telegram-канал. Пост в канал = добавленный
ролик: бот индексирует публикацию и отдаёт её пользователю через
`copy_message`, поэтому файлы никуда не перезаливаются и `file_id` не живёт в
коде. Тема берётся из тегов в подписи (`#снег`) или из текста подписи.

Ролик не по теме не отправляется вообще: нерелевантное видео обесценивает
остальные. Тема ищется и в текущем сообщении, и в нескольких последних —
иначе на «ещё» и «давай» видео не приходило бы никогда.

**Продажа идёт в три шага, а не в один.** Сначала бот предлагает узнать
условия (`prompts/offer_cta.txt`), по кнопке присылает состав и цены и только
после выбора ступени выставляет счёт. Раньше клик по «что входит» открывал
счёт сразу: человек видел сумму, не увидев продукта.

Состав для этого сообщения собирается из `prompts/product.txt` — из той же
карточки, которой пользуется ИИ. Второго файла с тем же составом нет намеренно:
два источника фактов о продукте разъезжаются на первой же правке.

Ступени тарифа описаны в `prompts/offer_plans.txt` строками `@buy_base`,
`@buy_premium`, `@buy_pro` — подписи с ценой правятся без кода. Цена в звёздах
задаётся отдельно (`STARS_PRICE_BASE`, `STARS_PRICE_PREMIUM`, `STARS_PRICE_PRO`):
текст правит тот, кто пишет тексты, деньги задаёт тот, у кого доступ к кассе.
Ступень без цены в звёздах уходит на внешнюю страницу оплаты, а если нет и её —
кнопка не показывается вовсе: кнопка, ведущая в извинение, хуже отсутствующей. Пока в карточке продукта остались метки `<<...>>`, оффер выключен
целиком, а модели запрещено обсуждать цены — чтобы бот не назвал живым людям
выдуманную цифру. Сверх того исходящие ответы проверяются на денежные
паттерны.

Оплата — либо Telegram Stars прямо в чате (`PAYMENTS_ENABLED=true`), либо
внешняя страница из `PURCHASE_URL`.

## Запуск

```bash
pip install -r requirements.txt
cp .env.example .env        # заполнить токен и ключ DeepSeek
python main.py
```

Без `PUBLIC_URL` бот работает поллингом — так удобно локально. На хостинге
адрес подставляется автоматически, и включается вебхук.

### Почему вебхук, а не поллинг

На бесплатном тарифе сервис засыпает после 15 минут тишины. Поллинг — наш
исходящий запрос, и спящий контейнер его не делает: бот мёртв, пока кто-то не
откроет URL. При вебхуке контейнер будит сам входящий запрос Telegram. Первое
сообщение после сна стоит холодного старта (30–50 секунд), но не теряется.

Побочный эффект приятный: Telegram запрещает `getUpdates` при включённом
вебхуке, поэтому случайно запущенный второй экземпляр больше не ворует
сообщения.

## Настройка

Ролики: создать приватный канал, добавить бота **администратором**, положить
`CONTENT_CHANNEL_ID` в окружение. Дальше бот наполнит библиотеку сам — при
запуске и по первому сообщению.

Массовая заливка:

```bash
python tools/import_videos.py ~/videos --dry-run   # показать разметку
python tools/import_videos.py ~/videos             # залить
```

Тема определяется по тексту рядом с роликом: файл `.txt` с тем же именем или
имя файла. Ролик, тему которого определить не удалось, пропускается — лучше
пропустить, чем отдать человеку видео не по теме.

## Подарок за вход

Чек-лист «30 шагов» лежит в `prompts/gift_checklist.txt` и правится без кода.
Отдаётся тремя путями: кнопкой под приветствием, командой `/checklist` и
ссылкой `t.me/<bot>?start=gift` — так подарок приходит сразу после перехода из
рекламы, без лишнего клика. Каждая выдача пишется событием `gift_sent`, иначе
конверсию из перехода в подписчика не посчитать.

Текст обязан помещаться в одно сообщение Telegram (4096 знаков) и размечаться
HTML-тегами: markdown в чате не отрендерится. И то, и другое проверяется
тестами — файл редактируют руками, и молча выйти за лимит легко.

Тот же текст собирается в PDF для Instagram, сайта и печати:

```bash
python tools/build_checklist_pdf.py           # assets/checklist_30_steps.pdf
python tools/build_checklist_pdf.py --check   # проверить исходник, ничего не писать
```

Источник один, иначе версия в чате и версия для рекламы разойдутся уже через
пару правок. Всё после метки `# CHAT-ONLY` в PDF не попадает: вопрос о том, что
разобрать дальше, в файле задавать некому.

## Догоняющие сообщения

Человек, который замолчал, раньше пропадал навсегда: бот отвечал только на
входящее. Теперь есть цепочка из `prompts/followups.txt` — три шага по
нарастающей тишине (час, сутки, трое суток), тексты и кнопки правятся без кода.

```
== 1                      ← через сколько часов тишины
Текст сообщения.
@offer 🔗 Что входит      ← кнопка к условиям и оплате
@gift 🎁 Заберу чек-лист  ← кнопка выдачи чек-листа
```

Правила простые и проверены тестами:

- за один запуск человек получает **один** шаг, а не всю цепочку сразу;
- ответил или нажал кнопку — отсчёт тишины начинается заново, уже отправленные
  шаги не повторяются;
- купил — выпадает из цепочки совсем;
- заблокировал бота — тоже, чтобы не долбиться в закрытую дверь каждый час;
- шаг с кнопкой `@offer` пропускается, пока карточка продукта не заполнена:
  звать покупать то, о чём бот ничего не знает, нельзя;
- ночью (21:00–09:00 МСК) очередь стоит и разбирается утром;
- кто молчит больше месяца, не получает ничего.

### Будильник обязан быть внешним

Планировщик внутри процесса здесь не работает: на бесплатном тарифе контейнер
засыпает через 15 минут тишины, и его собственный таймер засыпает вместе с ним.
Поэтому рассылку запускает HTTP-запрос снаружи — он же будит контейнер:

```bash
curl -X POST -H "X-Tasks-Secret: $TASKS_SECRET" https://<бот>/tasks/followups
```

Маршрут выключен, пока не задан `TASKS_SECRET`: открытая точка запуска
позволила бы кому угодно разослать письма всей базе. В `render.yaml` описан
Cron Job, который дёргает этот адрес раз в час.

## Служебные команды (только для `ADMIN_CHAT_ID`)

| Команда | Что делает |
|---|---|
| `/status` | что подключено: канал, сколько роликов, готов ли оффер |
| `/reindex <от> <до>` | пересобрать индекс перебором постов канала |
| `/migrate_legacy` | перенести старые ролики из кода в канал |

Bot API не умеет читать историю канала, поэтому `/reindex` перебирает
`message_id`, пересылая посты и тут же удаляя пересылку.

## Состояние и аналитика

Хранилище выбирается по переменным окружения, код при этом не меняется:

| Что задано | Где живёт состояние |
|---|---|
| `DATABASE_URL` | PostgreSQL — рабочий вариант |
| только `SHEETS_SCRIPT_URL` и `SHEETS_SECRET` | Google Sheets — что показать заказчику |
| ничего | память процесса, теряется при перезапуске |

Читает бот всегда кеш в памяти, поэтому разговор в чате не ждёт базу. Записи
копятся и уезжают пачкой раз в 10 секунд — кроме оплат: они пишутся немедленно
и умеют сообщить, что не записались.

### Postgres

Таблицы (`funnel_users`, `funnel_events`) создаются сами при первом запуске,
миграций накатывать не нужно. Что это даёт против таблицы: события перестают
жить в буфере на 500 записей и накапливаются целиком, а на воронку можно
смотреть запросом:

```sql
-- окупаемость сегментов лендинга
SELECT source, count(*) FILTER (WHERE is_premium) AS оплатили, count(*) AS всего
FROM funnel_users GROUP BY source ORDER BY всего DESC;

-- доходимость догоняющих сообщений
SELECT payload->>'step' AS шаг, count(*) FROM funnel_events
WHERE event = 'followup_sent' GROUP BY 1 ORDER BY 1;
```

**Переезд с таблицы происходит сам.** При первом старте с пустой базой бот
переносит строки из Sheets и пишет в лог, сколько пользователей и сколько из
них с оплаченным доступом. Срабатывает только на пустой базе, поэтому повторный
запуск ничего не затирает. Без переноса оплатившие потеряли бы доступ: он
выдаётся по полю `is_premium`, а в чистой базе его нет ни у кого.

Внутренний адрес Render (`postgresql://...@dpg-xxx-a/db`) работает только
изнутри его сети — с ноутбука подключиться не выйдет, это нормально. Внешний
адрес приходит с `?sslmode=require`; asyncpg такой параметр в строке не
принимает, поэтому бот вынимает его сам и включает TLS.

Что реально поднялось, видно в `/debug` — поле `store`. Проверять по переменной
окружения бесполезно: она задана, а база могла и не ответить. Недоступная база
бота не роняет: он работает из памяти и пишет ошибку в лог.

Оплаты — исключение: они пишутся в локальный журнал синхронно, ещё до сети, и
проигрываются при старте. Если запись не прошла, владельцу уходит алерт в
Telegram.
