# Handoff: два лендинга «Бег» (аудитория А и Б)

## Overview
Две продающие страницы для одного продукта — онлайн-гайда по естественной технике бега. Обе ведут к покупке премиум-тарифа. Отличаются только аудиторией и копирайтом:

- **Лендинг А — «Бег без боли»** — люди с болью в коленях, обращение на «вы», спокойный тон. Логика: боль → четыре причины → техника → гайд → покупка.
- **Лендинг Б — «Бег как сила»** — те, кто уже тренируется (зал, силовые), обращение на «ты», прямой тон. Логика: бег вылетает через 2 недели → четыре ошибки → механика шага → эффект для силовой → план на 21 день → покупка.

Обе страницы — одностраничные, с двумя тарифами (База / Премиум) и одним целевым действием: оплата премиума.

## About the Design Files
Файлы в `design/` — **дизайн-референсы, сделанные в HTML**. Это прототипы, показывающие вид, структуру и копирайт, а не продакшн-код для прямого копирования. Задача — **воссоздать эти страницы в реальном проекте**: любой уместный стек (Next.js / Astro / Vite + React / статический HTML+CSS), с нормальной семантикой, доступностью, метатегами и аналитикой.

Важно: `.dc.html` — это файлы среды прототипирования; они подключают `support.js` и рендерят разметку через runtime. **Копировать надо разметку и стили из тела файла**, а не сам механизм. Инлайновые стили в прототипе — следствие среды; в проде их нужно перенести в CSS/Tailwind/CSS-модули.

Ограничение прототипа: адаптив сделан только через `clamp()` и `grid-template-columns: repeat(auto-fit, minmax(...))`, без media-запросов. В проде можно оставить этот подход (он рабочий) или добавить обычные брейкпоинты — визуальная цель описана ниже.

## Fidelity
**High-fidelity.** Цвета, типографика, отступы и копирайт финальные. Воссоздавать близко к макету. Тексты не переписывать — они выверены под аудиторию; допустимы только правки плейсхолдеров.

## Interactions & Behavior
- Навигация — плавный скролл к `#program`, `#price`, `#faq` (`scroll-behavior: smooth`; учесть высоту sticky-хедера через `scroll-margin-top`).
- Hover: ссылки `#E8B23C` → `#F5CE77`; кнопки — лёгкое затемнение/подсветка фона, `transition: 150ms ease`.
- Кнопки тарифов ведут на внешние ссылки оплаты (плейсхолдеры ниже). Открывать в том же окне.
- FAQ (опционально) — аккордеон, первый пункт закрыт, анимация раскрытия 200ms.
- Изображения — `loading="lazy"` кроме hero.
- Адаптив: на мобильном все сетки складываются в одну колонку автоматически (auto-fit + minmax). Hero остаётся ≥82vh, шрифты по `clamp()`. Хит-таргеты кнопок ≥44px.
- Аналитика: события `cta_click` (hero / header / price_base / price_premium / final), `scroll_depth` по секциям.

## State Management
Страница статическая. Состояния нужны только для: аккордеона FAQ (открытый индекс) и, если добавите форму захвата email, — стандартные состояния формы (idle / submitting / success / error) с валидацией email по regex и текстом ошибки под полем.

## Деплой на Render
Два лендинга — два адреса. Варианты:

1. **Один статический сайт, два маршрута** (рекомендую): `/` → выбор или редирект, `/bez-boli` → лендинг А, `/sila` → лендинг Б. Один Render Static Site.
2. Два отдельных Static Site — если нужны разные домены под разные рекламные кампании.

Render — Static Site:
- Build Command: `npm ci && npm run build` (для Astro/Next static export/Vite)
- Publish Directory: `dist` (Astro/Vite) или `out` (Next `output: 'export'`)
- Node: зафиксировать версию в `.node-version` или `engines`
- Добавить `render.yaml` в корень репозитория для infrastructure-as-code
- SPA/маршруты: правило rewrite `/*` → `/index.html` только если это SPA; для многостраничной статики не нужно
- Заголовки: включить кэш `public, max-age=31536000, immutable` для `/assets/*`, `no-cache` для HTML
- Кастомный домен + HTTPS настраиваются в Render после первого деплоя

Что нужно сделать перед деплоем: заменить плейсхолдеры, подключить платёжные ссылки, добавить `<title>`, `<meta name="description">`, OG-теги и `favicon`, подключить аналитику, проверить страницу на мобильном и в Lighthouse.
